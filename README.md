# nixcon-quiz

Live multiplayer quiz for NixCon. Everyone who opens the page answers the same
question against the same clock. When the clock runs out the right answer is
revealed, and after every 10 questions (configurable) the leaderboard is shown
and all points reset for the next round.

## Running

```sh
nix run . -- --questions examples/questions --listen 127.0.0.1:8093
nix run . -- --questions questions --slides slides   # with break slides on /spectate
nix run . -- --check questions/   # validate the question files
nix run . -- --help               # timing and title flags
```

## Deploying on quiz.nixcon.org

```nix
{
  imports = [ nixcon-quiz.nixosModules.default ];
  services.nixcon-quiz = {
    enable = true;
    domain = "quiz.nixcon.org";  # nginx vhost + ACME, event stream unbuffered
    # questions = "/var/lib/nixcon-quiz/questions";  # the default, see below
    questionSeconds = 20;       # time to answer
    revealSeconds = 8;          # right answer on screen
    roundQuestions = 10;        # questions before the leaderboard; points reset after it
    leaderboardSeconds = 30;
    # slides = "/var/lib/nixcon-quiz/slides";  # the default; null for none
    slideSeconds = 15;          # how long each break slide is shown
  };
}
```

The questions are not deployed with the configuration: anything in the Nix
store is world-readable. Copy them to the server after deploying and restart
the service:

```sh
rsync -r --delete questions/ root@server:/var/lib/nixcon-quiz/questions/
ssh root@server systemctl restart nixcon-quiz
```

Until that directory has files in it the service is skipped instead of
failing the deployment. On every start it runs `--check` on the questions, so
a broken file stops the service with a message naming the file.

Break slides go the same way, and need no restart: the directory is scanned
again before every slide.

```sh
rsync -r --delete slides/ root@server:/var/lib/nixcon-quiz/slides/
```

The module doesn't touch nginx's global limits. Every player holds a client
and an upstream connection open, so for a big audience make sure
`worker_connections` and `worker_rlimit_nofile` are high enough.

## Questions

One TOML file per question in a directory. The real questions are not part of
this repository — anyone who can read them knows every answer — so `questions/`
is git-ignored; keep them somewhere private and point `questions` at them.
[`examples/questions/`](examples/questions) shows the format. Only `*.toml`
files are read, so notes can sit next to them.

```toml
question = "What is Nix's continuous build farm called?"
choices = ["Cerberus", "Hydra", "Kraken", "Medusa"]  # 2 to 6
answer = "Hydra"                                    # must match a choice exactly
explanation = "Shown with the answer."              # required: why it's right
```

Unknown keys are rejected, so a typo does not silently drop an option, and
errors name the offending file.

### Reviewing questions

```sh
nix run .#review            # or: python3 scripts/review.py questions
```

A terminal UI listing every question with its choices, the right answer and
the explanation, plus any problem that would make the server reject the file.
`o` marks a question ok and `f` flags it (`F` asks for a reason, `c` edits
the note); either moves on to the next one. `t` switches between all,
unreviewed, flagged, ok and invalid questions, `/` filters by text, `e`
opens the file in `$EDITOR` and reloads it. Marks are saved after every
change to `questions.review.json` (also git-ignored), so a review can be split
over sessions.

## How the game works

- The server owns the clock. Each question has absolute start and end times;
  clients receive them together with the server's current time and correct
  for their own clock skew, so every screen counts down to the same instant.
- Questions are drawn in a random order and only repeat once all have been
  asked.
- A correct answer scores 500 points plus up to 500 more depending on how much
  time was left. Wrong or missing answers score nothing.
- Names are generated by the server (`Lazy Thunk`, `Hermetic Flake`, …) and
  kept in an HttpOnly cookie, so a reload keeps your name and score.
- State lives in memory. Restarting the server starts a fresh game and gives
  everyone new names.

## Cheating

- The question files are never served. A client only ever receives the question
  currently being asked; which choice is correct, the explanation and how
  others voted are sent only after the question has closed.
- Answers are timestamped by the server and accepted only while the question
  is open. Players can change their answer until then; the last one counts,
  and its speed bonus is measured from when it was given.
- Scores change only at the reveal, so nothing can be learned from them while
  a question is open.
- What is not prevented: opening several private windows to get several
  players and spreading their answers across the choices. Each window is a
  separate player with its own random name and score.

## Frontend

The server renders all HTML ([maud](https://maud.lambda.xyz)); the browser
runs [htmx](https://htmx.org) with its SSE extension, both vendored under
`static/vendor/` so the page works without any CDN and under a strict CSP.

- `GET /` — the page with the current view already rendered. Issues the player
  cookie on first contact.
- `GET /spectate` — the livestream screen.
- `GET /api/events/spectate` — its stream: the whole view on every phase
  change, a `tally` event whenever the number of answers or players
  changes, and a `slide` event with the `<img>` of each new break slide.
- `GET /slides/<file>` — the break slides, named after a hash of their
  content so they can be cached forever.
- `GET /api/events?seen=<version>` — Server-Sent Events; on every phase change
  the server sends the player's re-rendered view as an HTML fragment and htmx
  swaps it in. `seen` names the state the page was rendered with; if nothing
  changed since, the stream waits for the next phase instead of re-rendering
  (which could undo a pick still on its way to the server).
- `POST /api/answer` — the answer form (`seq`, `choice`), posted by htmx
  whenever the picked radio button changes; `204` on success (sending again
  replaces the answer), `409` if the question is closed.

`static/clock.js` is the only hand-written script: it runs the countdowns and
the timer bar between server updates and closes the form when time is up.

The look follows [2026.nixcon.org](https://2026.nixcon.org): sky blue with
faded pixel clouds, a dark bar with the NixCon eagle, Press Start 2P for
labels, letters and numbers, and boxes with black pixel borders and notched
corners. Questions and answers stay in IBM Plex Mono so they read easily, and
are labelled like store paths. Your pick is blue, the right answer gold, and
red is only for what went wrong. Fonts and images are vendored under
`static/vendor/`.

## Livestream

Open `/spectate` (e.g. https://quiz.nixcon.org/spectate) in OBS as a browser
source at 1920×1080, or on a projector. It shows the same questions, timer,
reveal and leaderboard as the players, sized for 16:9 at any resolution, plus
a live count of answers and, along the bottom, a QR code, the address and how
to play. Watching doesn't make you a
player: no cookie, and it doesn't count as online. While a question is open
the screen only shows how many answered, never what.

The QR code points at `publicUrl` (`--public-url`), which the module sets to
`https://<domain>/`; without it the screen uses the host it was loaded from.

### Break slides

With `--slides DIR` (the module's `slides`) break slides — sponsor slides,
announcements — take the stage: the slide fills most of the screen with the
join details below it, and the game moves into a column on the right, in
smaller type and one choice per row. Each slide stays for `--slide-seconds`
(default 15); they go in file name order, so prefix names with numbers to
choose it. PDF, PNG, JPEG and WebP are shown; every page of a PDF is a
slide, rendered at 1920 pixels with poppler's `pdftoppm` (the package brings
it along; `cargo run` needs it on `PATH`, the dev shell has it). Every slide
is framed as 16:9; other shapes get white bars.

The directory is scanned before every slide, so files can be dropped in,
replaced or removed while the quiz runs; a PDF is rendered again only when it
changed. While the directory is empty or missing, the screen keeps the plain
layout with the join strip along the bottom.

Like the questions, the slides are not part of the repository: `slides/` is
git-ignored, a place to keep them for local runs.
